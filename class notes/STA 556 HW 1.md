It also means that git commands can be run through bash while actively editing the files to review changes and see any possible issues before committing the change.* What is the difference between the file existing in the codespace and the file being committed to git?A file existing in the codespace is like a file on a computer. Only you can see it and work on it. When it's committed to git, it's uploading it into the cloud. Other people can now see and change the file, but only once it's been committed.* What information did git diff provide before the commit?"git diff" showed the changes I'd made to the files that hadn't yet been committed.* Why is this a stronger reproducibility test than saying: “It runs on my computer”?You've run it on a machine different from the one you made the edits on, meaning that it runs in an environment different from the one you created.* Explain the difference among:  * saved in Codespace  * committed to Git  * pushed to GitHubWhen a file is saved in the codespace, it's only locally saved on that instance. Once it's committed to git, it's tentatively added to the repository. A change that's not yet saved. This means any potential errors or conflicts can be checked before it's officially saved. Pushing it to GitHub does just that. It saves the file online, where it now is a part of the repository permanently.
